# CoSupply MVP Technical Architecture

## 1. Architecture Overview

```text
Local Browser
  ↓ HTTP (development)
React SPA on localhost
  ↓ REST API /api/v1
Laravel API on localhost
  ↓
Local MySQL/MariaDB database
```

The application uses an API-first architecture so that a future mobile application can consume the same Laravel API.

## 2. Technology Decisions

| Area | Decision |
|---|---|
| Backend | Laravel REST API |
| Frontend | React SPA |
| Styling | Tailwind CSS |
| Client routing | React Router |
| Database | MySQL/MariaDB |
| API versioning | `/api/v1` |
| Authentication | Laravel Sanctum or equivalent secure API authentication |
| Development frontend | `http://localhost:5173` or configured local React URL |
| Development API | `http://localhost:8000/api/v1` or configured local Laravel URL |
| File storage | Laravel local filesystem |
| Queue | Not in MVP |
| Scheduler | Not in MVP |
| Notification | Email only |

## 3. Authentication and Authorization

- Guest can browse catalog and manage local cart only.
- Customer registration/login is required before creating a quotation request.
- Customer API endpoints must derive customer identity from the authenticated credential, never from a client-provided `customer_id`.
- Customer can access only records that belong to that authenticated customer.
- Admin and Customer credentials/roles must be separated by route middleware and authorization policies.
- Quotation link token, phone OTP, and guest quotation access are not included in MVP.

## 4. API Design Rules

- Prefix all API endpoints with `/api/v1`.
- Use consistent JSON response envelopes and validation error shapes.
- Use pagination for product, quotation, order, audit-log, and email-log lists.
- Use server-side authorization on every customer-owned resource endpoint.
- Do not expose sensitive file paths or storage locations in API responses.
- Use idempotency/transaction protection for quotation acceptance and order creation.

## 5. Local Development Configuration

Example local configuration:

```text
React SPA: http://localhost:5173
Laravel API: http://localhost:8000
API base URL: http://localhost:8000/api/v1
```

- Configure CORS for the local React development URL only.
- Keep API base URL in a frontend environment variable.
- Use local MySQL/MariaDB credentials in Laravel environment configuration.
- This specification does not define domain names, hosting, cPanel, Vercel, DNS, SSL, or production deployment.

## 6. Files and Media

Public assets:

```text
Product images
Product gallery images
Supplier logos
Category images
Quotation PDF files (generated by Admin)
```

Private assets:

```text
Receipt PDFs
Cash payment proofs
Customer signatures
Supplier communication attachments
```

Private files must be served only after authorization through Laravel, not by public static URL.

## 7. Notifications

MVP supports two notification channels:

- Email notification
- Database-backed in-app notification

Rules:

- Laravel stores in-app notification records in the database.
- React polls the authenticated notification endpoint every 60 seconds while the user is authenticated.
- The polling service must be created once at app-root/provider level, not separately on every page.
- Polling must stop on logout and should pause when the browser tab is hidden.
- Email is sent synchronously in MVP.
- Failure to send email must not roll back a successfully created quotation/order/status update.
- Store email delivery status/error and expose an Admin resend operation.
- WebSocket/realtime notification and mobile push notification are not included in MVP.

## 8. Deferred Infrastructure

The following are deferred until a future phase:

- Domain and production hosting setup
- cPanel and Vercel setup
- Long-running queue worker
- Scheduler/cron-driven business automation
- Object storage (S3/R2)
- Mobile push notification and WebSocket/realtime notification
- Mobile application client
